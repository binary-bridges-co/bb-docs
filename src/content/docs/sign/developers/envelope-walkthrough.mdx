El [inicio rápido](/sign/developers/quickstart/) termina en un `201`. Esta página recorre todo el
camino: subir un PDF, crear el sobre a su alrededor, añadir un segundo firmante, enviar, enterarte
por un webhook de que todos firmaron, y descargar el PDF sellado. Cada paso muestra la misma
llamada en `curl`, JavaScript y Java; elige una pestaña y se queda elegida.

Necesitas las cuatro variables de entorno del inicio rápido (`BBSIGN_BASE_URL`,
`BBSIGN_TOKEN_URL`, `BBSIGN_CLIENT_ID`, `BBSIGN_CLIENT_SECRET`), un PDF llamado `contract.pdf` y,
para las pestañas de JavaScript y Java, un `client` construido como en el inicio rápido.

## 1. Obtén un token

Los dos SDKs obtienen y renuevan los tokens por su cuenta. Aun así necesitas un token en crudo para
`curl` y para la subida del paso 2, que se hace con HTTP directo, sin el SDK. Un token vive
<Fact of={AUTH.tokenLifetimeSeconds} unit="s" />.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    TOKEN=$(curl -s -X POST "$BBSIGN_TOKEN_URL" \
      -d grant_type=client_credentials \
      -d client_id="$BBSIGN_CLIENT_ID" \
      -d client_secret="$BBSIGN_CLIENT_SECRET" | jq -r .access_token)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const tokenResponse = await fetch(process.env.BBSIGN_TOKEN_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: process.env.BBSIGN_CLIENT_ID,
        client_secret: process.env.BBSIGN_CLIENT_SECRET,
      }),
    })
    const { access_token: token } = await tokenResponse.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    HttpClient http = HttpClient.newHttpClient();
    String form = "grant_type=client_credentials"
            + "&client_id=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_ID"), StandardCharsets.UTF_8)
            + "&client_secret=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_SECRET"), StandardCharsets.UTF_8);
    HttpRequest tokenRequest = HttpRequest.newBuilder(URI.create(System.getenv("BBSIGN_TOKEN_URL")))
            .header("Content-Type", "application/x-www-form-urlencoded")
            .POST(HttpRequest.BodyPublishers.ofString(form))
            .build();
    String tokenJson = http.send(tokenRequest, HttpResponse.BodyHandlers.ofString()).body();
    String token = new ObjectMapper().readTree(tokenJson).get("access_token").asText();
    ```
  </TabItem>
</Tabs>

## 2. Sube el documento

`POST /api/v1/documents` es multipart con una sola parte, `file`. Solo se acepta
<Fact of={DOCUMENTS.contentType} />, hasta <Fact of={DOCUMENTS.maxUploadMb} unit="MB" />.
La respuesta es un `UploadedDocumentResponse`; guarda su `id`. Un documento que no se adjunta a un
sobre en <Fact of={DOCUMENTS.unassignedRetentionHours} unit="horas" /> se elimina.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    DOCUMENT_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/documents" \
      -H "Authorization: Bearer $TOKEN" \
      -F "file=@contract.pdf;type=application/pdf" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { openAsBlob } from 'node:fs'

    const form = new FormData()
    form.set('file', await openAsBlob('contract.pdf', { type: 'application/pdf' }), 'contract.pdf')

    const upload = await fetch(`${process.env.BBSIGN_BASE_URL}/api/v1/documents`, {
      method: 'POST',
      headers: { Authorization: `Bearer ${token}` },
      body: form,
    })
    const { id: documentId } = await upload.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    OkHttpClient okHttp = new OkHttpClient();
    RequestBody multipart = new MultipartBody.Builder().setType(MultipartBody.FORM)
            .addFormDataPart("file", "contract.pdf",
                    RequestBody.create(new File("contract.pdf"), MediaType.get("application/pdf")))
            .build();
    Request upload = new Request.Builder()
            .url(System.getenv("BBSIGN_BASE_URL") + "/api/v1/documents")
            .header("Authorization", "Bearer " + token)
            .post(multipart)
            .build();
    UUID documentId;
    try (Response response = okHttp.newCall(upload).execute()) {
        documentId = UUID.fromString(new ObjectMapper().readTree(response.body().string()).get("id").asText());
    }
    ```
  </TabItem>
</Tabs>

Los métodos generados del SDK para subidas envían JSON, no multipart, así que las pestañas de
JavaScript y Java usan el cliente HTTP de la plataforma (okhttp ya es una dependencia del SDK de
Java). También puedes adjuntar un archivo a un borrador existente con
`POST /api/v1/envelopes/{id}/documents`, con el mismo nombre de parte.

## 3. Crea el sobre

Pasa el id subido en `documentIds`. `title` es el único campo obligatorio; un sobre no se puede
enviar sin al menos un firmante y un documento.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    ENVELOPE_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes" \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d "{
        \"title\": \"Service agreement\",
        \"documentIds\": [\"$DOCUMENT_ID\"],
        \"otpRequired\": true,
        \"signers\": [{\"email\": \"ana@example.com\", \"name\": \"Ana Perez\", \"signOrder\": 1}]
      }" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const envelope = await client.envelopes.createEnvelope({
      createEnvelopeRequest: {
        title: 'Service agreement',
        documentIds: [documentId],
        otpRequired: true,
        signers: [{ email: 'ana@example.com', name: 'Ana Perez', signOrder: 1 }],
      },
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    EnvelopeResponse envelope = client.execute(client.envelopes().createEnvelope(
            new CreateEnvelopeRequest()
                    .title("Service agreement")
                    .documentIds(List.of(documentId))
                    .otpRequired(true)
                    .signers(List.of(new CreateSignerSpec()
                            .email("ana@example.com")
                            .name("Ana Perez")
                            .signOrder(1)))));
    ```
  </TabItem>
</Tabs>

## 4. Añade un firmante

Se pueden añadir firmantes mientras el sobre es un `DRAFT`. `signOrder` solo importa cuando
`sequentialSigning` es true; si no, todos los firmantes reciben su enlace a la vez.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/signers" \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"email": "luis@example.com", "name": "Luis Gomez", "signOrder": 2}'
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    await client.envelopes.addSigner({
      id: envelope.id,
      addSignerRequest: { email: 'luis@example.com', name: 'Luis Gomez', signOrder: 2 },
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    client.execute(client.envelopes().addSigner(envelope.getId(),
            new AddSignerRequest().email("luis@example.com").name("Luis Gomez").signOrder(2)));
    ```
  </TabItem>
</Tabs>

## 5. Envía

Este es el punto sin retorno: los documentos y los firmantes se congelan, cada firmante recibe por
correo un enlace válido por <Fact of={ENVELOPE.linkTtlHoursDefault} unit="horas" /> por defecto,
y se dispara `envelope.sent`. La respuesta es un `SendResponse` con los tokens de firma por
firmante.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/send" \
      -H "Authorization: Bearer $TOKEN"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const sent = await client.envelopes.sendEnvelope({ id: envelope.id })
    console.log('Sent', sent.envelopeId)
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    SendResponse sent = client.execute(client.envelopes().sendEnvelope(envelope.getId()));
    System.out.println("Sent " + sent.getEnvelopeId());
    ```
  </TabItem>
</Tabs>

## 6. Recibe `envelope.completed`

Registra un webhook en **Configuración**, pestaña **Webhooks**, suscrito a `envelope.completed`.
Cuando firma el último firmante, bb-sign publica un evento firmado en tu URL. Verifica la firma
sobre el cuerpo en crudo, responde `2xx` y luego haz el trabajo. El payload lleva el id y el estado
del sobre, no el documento: ese lo obtienes en el paso 7. [Webhooks](/sign/developers/webhooks/)
cubre la entrega y los reintentos.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```http
    POST /webhooks/bb-sign HTTP/1.1
    Content-Type: application/json
    X-BBSign-Event-Id: 3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f
    X-BBSign-Event-Type: envelope.completed
    X-BBSign-Signature: t=1760000000,v1=5f1a...

    {"id":"3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f","type":"envelope.completed","apiVersion":"2026-08-09",
     "createdAt":"2026-10-10T14:22:31Z","data":{"envelope":{"id":"...","title":"Service agreement",
     "status":"COMPLETED","createdAt":"...","expiresAt":null}}}
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import express from 'express'
    import { verifyWebhookSignature } from '@binarybridges/bb-sign-sdk/webhooks'

    const app = express()
    app.use(express.json({ verify: (req, _res, buf) => { req.rawBody = buf } }))

    app.post('/webhooks/bb-sign', (req, res) => {
      if (!verifyWebhookSignature(req.get('X-BBSign-Signature'), req.rawBody, process.env.BBSIGN_WEBHOOK_SECRET)) {
        return res.sendStatus(401)
      }
      const event = JSON.parse(req.rawBody.toString('utf8'))
      res.sendStatus(200)
      if (event.type === 'envelope.completed') void downloadSigned(event.data.envelope.id)
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    @PostMapping("/webhooks/bb-sign")
    public ResponseEntity<Void> receive(
            @RequestHeader("X-BBSign-Signature") String signature,
            @RequestBody byte[] rawBody) throws IOException {

        if (!Webhooks.verify(signature, rawBody, System.getenv("BBSIGN_WEBHOOK_SECRET"))) {
            return ResponseEntity.status(401).build();
        }
        WebhookEvent event = new ObjectMapper().readValue(rawBody, WebhookEvent.class);
        if ("envelope.completed".equals(event.getType())) {
            executor.submit(() -> downloadSigned(event.getData().getEnvelope().getId()));
        }
        return ResponseEntity.ok().build();
    }
    ```
  </TabItem>
</Tabs>

## 7. Lista los documentos y descarga el PDF firmado

`GET /api/v1/envelopes/{id}/documents` devuelve cada documento con un `downloadUrl` (el original)
y, cuando el sobre está `COMPLETED`, un `signedUrl` (la copia sellada). Ambos son enlaces
prefirmados válidos por <Fact of={ENVELOPE.downloadUrlSeconds} unit="s" />, y son `null` a menos
que la credencial tenga `document:download` en el espacio de trabajo del sobre. Trátalos como
secretos: entregan el archivo sin token.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    SIGNED_URL=$(curl -s "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/documents" \
      -H "Authorization: Bearer $TOKEN" | jq -r '.[0].signedUrl')

    curl -s -o contract-signed.pdf "$SIGNED_URL"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { writeFile } from 'node:fs/promises'

    async function downloadSigned(envelopeId) {
      const documents = await client.envelopes.listEnvelopeDocuments({ id: envelopeId })
      for (const document of documents) {
        const pdf = await fetch(document.signedUrl)
        await writeFile(`${document.id}-signed.pdf`, Buffer.from(await pdf.arrayBuffer()))
      }
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    void downloadSigned(UUID envelopeId) throws Exception {
        List<DocumentWithUrlsResponse> documents =
                client.execute(client.envelopes().listEnvelopeDocuments(envelopeId));
        HttpClient http = HttpClient.newHttpClient();
        for (DocumentWithUrlsResponse document : documents) {
            HttpRequest download = HttpRequest.newBuilder(URI.create(document.getSignedUrl())).build();
            http.send(download, HttpResponse.BodyHandlers.ofFile(Path.of(document.getId() + "-signed.pdf")));
        }
    }
    ```
  </TabItem>
</Tabs>

Archiva lo que descargas: bb-sign conserva los documentos firmados durante un plazo fijo, y
conservarlos después es responsabilidad de la organización. Ver
[Alcance y conservación](/sign/legal/retention/).

## Si un POST agotó el tiempo de espera: lista antes de reintentar

<Aside type="caution" title="Una escritura con resultado desconocido nunca se reintenta">
  Si `POST /api/v1/envelopes` o `/send` agotan el tiempo de espera, el resultado es desconocido: el
  sobre puede existir o puede que ya se haya enviado por correo a personas reales. Ningún SDK lo
  reintenta, y la API no tiene clave de idempotencia. **Lista antes de reintentar.** Busca por
  título con `GET /api/v1/envelopes?title=...` (o `getEnvelope` si guardaste el id); solo cuando no
  hay nada envías de nuevo. Los SDKs informan este caso como estado `0` (`BbSignError.statusCode`
  en JavaScript, `BbSignException.statusCode()` en Java).
</Aside>

`429` y `503` sí se reintentan, incluso para `POST`: significan que el servidor explícitamente no
procesó la petición.

## Cada sobre vive en un espacio de trabajo

El sobre de arriba se archivó en **General** porque no se pasó `workspaceId`. Una credencial solo
llega a los espacios de trabajo que un administrador le concedió; `GET /api/v1/workspaces` los
lista, y un `EnvelopeResponse` lleva `workspaceId` y `workspaceName`. Los sobres de espacios que la
credencial no puede leer responden `404` y nunca aparecen en las listas.
