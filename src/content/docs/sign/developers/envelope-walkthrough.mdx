Esta guía recorre el flujo completo de una integración: subir un PDF, crear el sobre, agregar un
segundo firmante, enviarlo, recibir por webhook la confirmación de que todos firmaron, descargar
el PDF sellado y comprobar su hash, y guardar el certificado de evidencia. Continúa donde termina el [inicio rápido](/sign/developers/quickstart/). Cada paso
muestra la misma llamada en `curl`, JavaScript y Java; la pestaña elegida se mantiene en toda la
página.

Requisitos: las cuatro variables de entorno del inicio rápido (`BBSIGN_BASE_URL`,
`BBSIGN_TOKEN_URL`, `BBSIGN_CLIENT_ID`, `BBSIGN_CLIENT_SECRET`), un PDF llamado `contract.pdf` y,
para las pestañas de JavaScript y Java, un `client` construido como en el inicio rápido.

## 1. Obtener un token

Ambos SDKs obtienen y renuevan los tokens automáticamente. El token explícito se necesita para
`curl` y para la subida del paso 2, que se hace con HTTP directo. Un token es válido durante
<Fact of={AUTH.tokenLifetimeSeconds} unit="s" />.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    TOKEN=$(curl -s -X POST "$BBSIGN_TOKEN_URL" \
      -d grant_type=client_credentials \
      -d client_id="$BBSIGN_CLIENT_ID" \
      -d client_secret="$BBSIGN_CLIENT_SECRET" | jq -r .access_token)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const tokenResponse = await fetch(process.env.BBSIGN_TOKEN_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: process.env.BBSIGN_CLIENT_ID,
        client_secret: process.env.BBSIGN_CLIENT_SECRET,
      }),
    })
    const { access_token: token } = await tokenResponse.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    HttpClient http = HttpClient.newHttpClient();
    String form = "grant_type=client_credentials"
            + "&client_id=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_ID"), StandardCharsets.UTF_8)
            + "&client_secret=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_SECRET"), StandardCharsets.UTF_8);
    HttpRequest tokenRequest = HttpRequest.newBuilder(URI.create(System.getenv("BBSIGN_TOKEN_URL")))
            .header("Content-Type", "application/x-www-form-urlencoded")
            .POST(HttpRequest.BodyPublishers.ofString(form))
            .build();
    String tokenJson = http.send(tokenRequest, HttpResponse.BodyHandlers.ofString()).body();
    String token = new ObjectMapper().readTree(tokenJson).get("access_token").asText();
    ```
  </TabItem>
</Tabs>

## 2. Subir el documento

`POST /api/v1/documents` recibe multipart con una sola parte, `file`. Acepta
<Fact of={DOCUMENTS.contentType} /> de hasta <Fact of={DOCUMENTS.maxUploadMb} unit="MB" />.
La respuesta es un `UploadedDocumentResponse`; conserve su `id`. Un documento que no se adjunta a
un sobre en <Fact of={DOCUMENTS.unassignedRetentionHours} unit="horas" /> se elimina.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    DOCUMENT_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/documents" \
      -H "Authorization: Bearer $TOKEN" \
      -F "file=@contract.pdf;type=application/pdf" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { openAsBlob } from 'node:fs'

    const form = new FormData()
    form.set('file', await openAsBlob('contract.pdf', { type: 'application/pdf' }), 'contract.pdf')

    const upload = await fetch(`${process.env.BBSIGN_BASE_URL}/api/v1/documents`, {
      method: 'POST',
      headers: { Authorization: `Bearer ${token}` },
      body: form,
    })
    const { id: documentId } = await upload.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    OkHttpClient okHttp = new OkHttpClient();
    RequestBody multipart = new MultipartBody.Builder().setType(MultipartBody.FORM)
            .addFormDataPart("file", "contract.pdf",
                    RequestBody.create(new File("contract.pdf"), MediaType.get("application/pdf")))
            .build();
    Request upload = new Request.Builder()
            .url(System.getenv("BBSIGN_BASE_URL") + "/api/v1/documents")
            .header("Authorization", "Bearer " + token)
            .post(multipart)
            .build();
    UUID documentId;
    try (Response response = okHttp.newCall(upload).execute()) {
        documentId = UUID.fromString(new ObjectMapper().readTree(response.body().string()).get("id").asText());
    }
    ```
  </TabItem>
</Tabs>

Los métodos generados del SDK envían JSON, por lo que las subidas multipart de las pestañas de
JavaScript y Java usan el cliente HTTP de la plataforma (okhttp ya es una dependencia del SDK de
Java). También puede adjuntar un archivo a un borrador existente con
`POST /api/v1/envelopes/{id}/documents`, con el mismo nombre de parte.

## 3. Crear el sobre

Envíe el id del documento en `documentIds`. `title` es el único campo obligatorio; para enviar el
sobre se requieren al menos un firmante y un documento.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    ENVELOPE_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes" \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d "{
        \"title\": \"Service agreement\",
        \"documentIds\": [\"$DOCUMENT_ID\"],
        \"otpRequired\": true,
        \"signers\": [{\"email\": \"ana@example.com\", \"name\": \"Ana Perez\", \"signOrder\": 1}]
      }" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const envelope = await client.envelopes.createEnvelope({
      createEnvelopeRequest: {
        title: 'Service agreement',
        documentIds: [documentId],
        otpRequired: true,
        signers: [{ email: 'ana@example.com', name: 'Ana Perez', signOrder: 1 }],
      },
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    EnvelopeResponse envelope = client.execute(client.envelopes().createEnvelope(
            new CreateEnvelopeRequest()
                    .title("Service agreement")
                    .documentIds(List.of(documentId))
                    .otpRequired(true)

                            .email("ana@example.com")
    ```

## 4. Agregar un firmante

Puede agregar firmantes mientras el sobre está en `DRAFT`. `signOrder` aplica cuando
`sequentialSigning` es true; en caso contrario, todos los firmantes reciben su enlace al mismo
tiempo.

<Tabs syncKey="lang">
  <TabItem label="curl">

    ```bash
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"email": "luis@example.com", "name": "Luis Gomez", "signOrder": 2}'
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js

      id: envelope.id,
    ```

  <TabItem label="Java">

## 5. Enviar el sobre

Al enviar, los documentos y los firmantes quedan fijos, cada firmante recibe por correo un enlace
válido durante <Fact of={ENVELOPE.linkTtlHoursDefault} unit="horas" /> de forma predeterminada y
se emite `envelope.sent`. La respuesta es un `SendResponse` con los tokens de firma de cada
firmante.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/send" \
      -H "Authorization: Bearer $TOKEN"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const sent = await client.envelopes.sendEnvelope({ id: envelope.id })
    console.log('Sent', sent.envelopeId)
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    SendResponse sent = client.execute(client.envelopes().sendEnvelope(envelope.getId()));
    System.out.println("Sent " + sent.getEnvelopeId());
    ```
  </TabItem>
</Tabs>

## 6. Recibir `envelope.completed`

Registre un webhook en **Configuración**, pestaña **Webhooks**, suscrito a `envelope.completed` y a
`envelope.evidence_issued`. Cuando firma el último firmante, bb-sign envía **una sola vez** por
sobre y suscripción un evento firmado a su URL, con el certificado de evidencia si está listo a
tiempo; si no lo está, el certificado llega después en `envelope.evidence_issued`. Verifique la
firma sobre el cuerpo original, responda `2xx` y luego procese el evento.

El payload trae el sobre, el SHA-256 de cada documento (`data.documents[].signedSha256`), la ruta
de los documentos, los hashes y la ruta del certificado de evidencia y las fechas de conservación
(`data.retention`). Los archivos se obtienen en el paso 7. [Webhooks](/sign/developers/webhooks/)
describe la entrega y los reintentos.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```http
    POST /webhooks/bb-sign HTTP/1.1
    Content-Type: application/json
    X-BBSign-Event-Id: 3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f
    X-BBSign-Event-Type: envelope.completed
    X-BBSign-Signature: t=1760000000,v1=5f1a...

    {"id":"3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f","type":"envelope.completed","apiVersion":"2026-08-09",
     "createdAt":"2026-10-10T14:22:31Z","data":{"envelope":{"id":"...","title":"Service agreement",
     "status":"COMPLETED","createdAt":"...","expiresAt":null},
     "evidenceStatus":"ISSUED","signedDocumentsStatus":"READY",
     "documents":[{"documentId":"...","filename":"contract.pdf","originalSha256":"9f2c...","signedSha256":"4b7e..."}],
     "documentsPath":"/api/v1/envelopes/.../documents",
     "evidenceCertificate":{"evidenceId":"...","sha256":"c01d...","auditTrailSha256":"77aa...","language":"es",
      "downloadPath":"/api/v1/envelopes/.../evidence-certificate/download"},
     "auditChainHead":{"seq":12,"hash":"e3b0...","auditCoverage":{"level":"FULL","fullRows":12,"partialRows":0,
      "lastPartialAt":null,"reasons":[],"migratedAt":null}},
     "retention":{"archivesAt":null,"deletesAt":"2027-10-16T00:00:00Z"}}}
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import express from 'express'
    import { verifyWebhookSignature } from '@binarybridges/bb-sign-sdk/webhooks'

    const app = express()
    app.use(express.json({ verify: (req, _res, buf) => { req.rawBody = buf } }))

    app.post('/webhooks/bb-sign', (req, res) => {
      if (!verifyWebhookSignature(req.get('X-BBSign-Signature'), req.rawBody, process.env.BBSIGN_WEBHOOK_SECRET)) {
        return res.sendStatus(401)
      }
      const event = JSON.parse(req.rawBody.toString('utf8'))
      res.sendStatus(200)
      if (event.type === 'envelope.completed') void downloadSigned(event.data)
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    @PostMapping("/webhooks/bb-sign")
    public ResponseEntity<Void> receive(
            @RequestHeader("X-BBSign-Signature") String signature,
            @RequestBody byte[] rawBody) throws IOException {

        if (!Webhooks.verify(signature, rawBody, System.getenv("BBSIGN_WEBHOOK_SECRET"))) {
            return ResponseEntity.status(401).build();
        }
        WebhookEvent event = MAPPER.readValue(rawBody, WebhookEvent.class);
        if (event.getType() == WebhookEvent.TypeEnum.ENVELOPE_COMPLETED) {
            executor.submit(() -> {
                downloadSigned(event.getData());
                return null;
            });
        }
        return ResponseEntity.ok().build();
    }
    ```

    `getType()` devuelve un enum (`WebhookEvent.TypeEnum`), no un `String`: compárelo con sus
    constantes. `MAPPER` es el `ObjectMapper` de la página del [SDK de Java](/sign/sdks/java/#verificar-un-webhook),
    con fechas ISO-8601 y sin fallar ante campos nuevos; un `new ObjectMapper()` sin configurar no
    puede leer el evento.
  </TabItem>
</Tabs>

## 7. Descargar el PDF firmado y comprobar su hash

`GET /api/v1/envelopes/{id}/documents` (la ruta de `data.documentsPath`) devuelve cada documento con
un `downloadUrl` (el original) y un `signedUrl` (la copia sellada). Ambos son enlaces prefirmados
válidos durante <Fact of={ENVELOPE.downloadUrlSeconds} unit="s" />. Trátelos como secretos: dan
acceso al archivo sin token. `signedUrl` es `null` cuando:

- la credencial no tiene `document:download` en el espacio de trabajo del sobre;
- la copia firmada no se puede descargar ahora: `signed.availability` es `ARCHIVED`,
  `RESTORE_IN_PROGRESS` o `DELETED` (ver [Conservación y restauración](/sign/developers/webhooks/#conservación-y-restauración)).
  {!RETENTION_IMPLEMENTED.documentsArchiveTransitionLive.value && 'Hoy ningún archivo pasa a almacenamiento de archivo, de modo que en producción este caso solo se da al terminar el plazo de conservación.'}

Calcule el SHA-256 de cada PDF descargado y compárelo con `data.documents[].signedSha256`. Si
`data.signedDocumentsStatus` es `PREPARING`, ese hash todavía no se conoce: no lo compare y vuelva a
descargar más tarde.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    DOCUMENTS=$(curl -s "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/documents" \
      -H "Authorization: Bearer $TOKEN")

    echo "$DOCUMENTS" | jq -r '.[0].signed.availability'   # AVAILABLE or RESTORED: downloadable
    curl -s -o contract-signed.pdf "$(echo "$DOCUMENTS" | jq -r '.[0].signedUrl')"
    shasum -a 256 contract-signed.pdf                      # must equal data.documents[0].signedSha256
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { createHash } from 'node:crypto'
    import { writeFile } from 'node:fs/promises'

    async function downloadSigned(data) {
      const expected = new Map((data.documents ?? []).map((d) => [d.documentId, d.signedSha256]))
      const documents = await client.envelopes.listEnvelopeDocuments({ id: data.envelope.id })
      for (const document of documents) {
        if (!document.signedUrl) continue // not downloadable now: see document.signed.availability
        const pdf = Buffer.from(await (await fetch(document.signedUrl)).arrayBuffer())
        const sha256 = createHash('sha256').update(pdf).digest('hex')
        const want = expected.get(document.id)
        if (want && want !== sha256) throw new Error(`SHA-256 mismatch for document ${document.id}`)
        await writeFile(`${document.id}-signed.pdf`, pdf)
      }
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    void downloadSigned(WebhookEventData data) throws Exception {
        Map<UUID, String> expected = new HashMap<>();
        if (data.getDocuments() != null) {
            for (WebhookEventDocument d : data.getDocuments()) {
                expected.put(d.getDocumentId(), d.getSignedSha256());
            }
        }
        List<DocumentWithUrlsResponse> documents =
                client.execute(client.envelopes().listEnvelopeDocuments(data.getEnvelope().getId()));
        HttpClient http = HttpClient.newHttpClient();
        for (DocumentWithUrlsResponse document : documents) {
            if (document.getSignedUrl() == null) {
                continue; // not downloadable now: see document.getSigned().getAvailability()
            }
            HttpRequest download = HttpRequest.newBuilder(URI.create(document.getSignedUrl())).build();
            byte[] pdf = http.send(download, HttpResponse.BodyHandlers.ofByteArray()).body();
            String sha256 = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(pdf));
            String want = expected.get(document.getId());
            if (want != null && !want.equals(sha256)) {
                throw new IOException("SHA-256 mismatch for document " + document.getId());
            }
            Files.write(Path.of(document.getId() + "-signed.pdf"), pdf);
        }
    }
    ```
  </TabItem>
</Tabs>

## 8. Guardar el certificado de evidencia

Cuando `data.evidenceStatus` es `ISSUED`, el [certificado de evidencia](/sign/concepts/evidence-certificate/)
está listo. `GET data.evidenceCertificate.downloadPath` responde un JSON con `downloadUrl` (el PDF) y
`auditTrailUrl` (el registro de auditoría congelado), ambos válidos durante
<Fact of={EVIDENCE.downloadLinkSeconds} unit="s" />, y con sus hashes. Requiere
<code>{EVIDENCE.downloadPermission.value}</code>, y cada llamada queda registrada en el registro del
sobre. Los SDKs no incluyen esta ruta: se llama por HTTP con el token del paso 1. Si el estado es
`PENDING`, espere `envelope.evidence_issued`.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    EVIDENCE=$(curl -s "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/evidence-certificate/download" \
      -H "Authorization: Bearer $TOKEN")

    curl -s -o evidence-certificate.pdf "$(echo "$EVIDENCE" | jq -r .downloadUrl)"
    shasum -a 256 evidence-certificate.pdf                 # must equal .sha256 and data.evidenceCertificate.sha256
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    async function downloadEvidence(data) {
      const response = await fetch(`${process.env.BBSIGN_BASE_URL}${data.evidenceCertificate.downloadPath}`, {
        headers: { Authorization: `Bearer ${token}` },
      })
      const { downloadUrl, sha256 } = await response.json()
      const pdf = Buffer.from(await (await fetch(downloadUrl)).arrayBuffer())
      if (createHash('sha256').update(pdf).digest('hex') !== sha256) throw new Error('SHA-256 mismatch')
      await writeFile(`${data.envelope.id}-evidence-certificate.pdf`, pdf)
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    void downloadEvidence(WebhookEventData data) throws Exception {
        HttpClient http = HttpClient.newHttpClient();
        HttpRequest links = HttpRequest.newBuilder(
                        URI.create(System.getenv("BBSIGN_BASE_URL") + data.getEvidenceCertificate().getDownloadPath()))
                .header("Authorization", "Bearer " + token)
                .build();
        EvidenceCertificateDownloadResponse evidence = MAPPER.readValue(
                http.send(links, HttpResponse.BodyHandlers.ofString()).body(),
                EvidenceCertificateDownloadResponse.class);
        byte[] pdf = http.send(HttpRequest.newBuilder(URI.create(evidence.getDownloadUrl())).build(),
                HttpResponse.BodyHandlers.ofByteArray()).body();
        String sha256 = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(pdf));
        if (!sha256.equals(evidence.getSha256())) {
            throw new IOException("SHA-256 mismatch for the evidence certificate");
        }
        Files.write(Path.of(data.getEnvelope().getId() + "-evidence-certificate.pdf"), pdf);
    }
    ```
  </TabItem>
</Tabs>

Archive lo que descarga: bb-sign conserva cada archivo del sobre durante
<Fact of={RETENTION_POLICY.retentionDays} unit="días" /> (la copia firmada desde la finalización y
el certificado desde su emisión), y `data.retention.deletesAt` indica desde qué fecha dejan de estar
disponibles. La conservación posterior es responsabilidad de la organización. Consulte
[Alcance y conservación](/sign/legal/retention/).

## Reintentar un POST sin respuesta

<Aside type="caution" title="Liste antes de reintentar una escritura">
  Si `POST /api/v1/envelopes` o `/send` agotan el tiempo de espera, el resultado es desconocido: el
  sobre puede existir o ya puede haberse enviado por correo a los firmantes. Los SDKs no reintentan
  estas llamadas y la API no usa claves de idempotencia. **Liste antes de reintentar**: busque por
  título con `GET /api/v1/envelopes?title=...` (o use `getEnvelope` si conserva el id) y envíe de
  nuevo solo si el sobre no aparece. Los SDKs reportan este caso como estado `0`
  (`BbSignError.statusCode` en JavaScript, `BbSignException.statusCode()` en Java).
</Aside>

`429` y `503` se reintentan también en `POST`, porque indican que el servidor no procesó la
solicitud.

## Espacio de trabajo del sobre

El sobre de este recorrido quedó en **General** porque no se envió `workspaceId`. Una
credencial accede a los espacios de trabajo que un administrador le asignó; `GET /api/v1/workspaces`
los lista, y cada `EnvelopeResponse` incluye `workspaceId` y `workspaceName`. Los sobres de
espacios que la credencial no puede leer responden `404` y no aparecen en las listas.
