The **quota** defines your organization's use of bb-sign: how many envelopes it creates per period,
how many users it has, how much storage it occupies and how many signers each envelope admits. Binary
Bridges configures it according to the agreement with each customer, and the organization
administrator can consult it at any time to anticipate their needs.

## What it measures

| Limit | What it counts | Where it shows |
| --- | --- | --- |
| Envelopes | Envelopes created in the current period. | **Envelopes**, in the **Quota & Usage** panel. |
| Users | Users in the organization. | **Max Users**. |
| Storage | Size of the documents attached to envelopes. | **Storage**. |
| Signers per envelope | Signers one envelope admits. | **Max Signers/Envelope**. |

Each limit can be **unlimited**, which is the initial setting of every new organization: the panel
shows **Unlimited** for all four. If the organization does not have a quota configured yet, the
panel says so.

## Periods

The envelope limit is counted per period. The other limits (users, storage and signers per envelope)
are totals. There are three period types:

The **Quota & Usage** panel shows the current period and, if it has one, its end date. When a custom
period reaches its date, Binary Bridges renews it so that the organization can keep creating and
sending envelopes; until then, the application shows "No active usage period.".

## Usage warning

When the usage of a limit reaches <Fact of={QUOTA.warningThresholdPct} unit="%" /> of its maximum,
bb-sign emits a quota warning. This is every organization's initial threshold, and Binary Bridges
can adjust it in **Warning Threshold (%)**. The warning is the right moment to request an increase,
before the limit is reached.

## When a limit is reached

When an action exceeds a limit, the application says which one it was and how to continue (the API
answers with status <Fact of={QUOTA.httpStatusWhenExhausted} />):

| Limit reached | Message |
| --- | --- |
| Envelopes | "Your organization has reached its envelope limit for this period. Ask your administrator to raise the limit." |
| Signers per envelope | "This envelope has more signers than your plan allows." |
| Storage | "Your organization has run out of document storage. Ask your administrator to raise the limit." |
| Users | "Your organization has reached its user limit." |

To raise a limit, the organization administrator contacts their account manager at Binary Bridges.

If Binary Bridges suspends the plan, envelope creation and sending stop until it is reactivated, and
existing envelopes remain available to consult.

<Aside type="note" title="Envelopes count from creation">
  An envelope consumes quota the moment it is created, whether or not it is sent, and that usage
  remains even if the envelope is cancelled or expires. Likewise, a document's storage remains even
  if the document is deleted. Keep this in mind when creating test envelopes.
</Aside>

Storage is charged when the envelope is created with its documents; documents uploaded to the wizard
that do not belong to an envelope yet do not consume quota (see
[Documents](/en/sign/concepts/documents/)).

## Who configures the quota

The **platform administrator** (Binary Bridges) configures the quota from the **Quota
Configuration** panel, where they can set it, update it, renew the period, suspend and activate the
plan.

The **organization administrator** consults the **Quota & Usage** panel, with the current usage of
each limit and the current period. You will find how to read it in
[Quota and usage](/en/sign/admin/quota-and-usage/). Organization members see the messages above when
a limit is reached.
