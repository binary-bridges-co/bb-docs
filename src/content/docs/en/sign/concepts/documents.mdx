An envelope contains one or more documents, and every signer signs all of them. You decide where on
each document each signer's seal appears. This page explains which files bb-sign accepts, how they
are handled while you prepare the envelope and how to place the seals.

## Format and size

bb-sign works with documents in <Fact of={DOCUMENTS.contentType} /> format. If you have a document in
Word, as an image or in another format, convert it to PDF before uploading it.

Each file can weigh up to <Fact of={DOCUMENTS.maxUploadMb} unit="MB" />. If a file is larger, the
application shows "That file is too large."; shrink the PDF (for example, by lowering the resolution
of its images) and upload it again.

An envelope needs at least one document to be sent, and every document must have its fingerprint
recorded (see [Each document's fingerprint](#each-documents-fingerprint)). bb-sign computes it when
the file is uploaded; if one is missing, sending shows "One of the documents does not have its
fingerprint recorded yet, so the envelope cannot be sent. Wait a few minutes or upload it again.".
Wait a few minutes, because bb-sign fills in the fingerprints of older drafts in the background, or
remove the document and upload it again.

## Documents uploaded before sending

The wizard uploads documents in its third step, before the envelope is created. Until you press
**Send Envelope**, those files are **unassigned**: they belong to your organization, but not yet to
an envelope.

- **They do not consume quota.** Storage is charged when the envelope is created. See
  [Quotas](/en/sign/concepts/quotas/).
- **They have a cap per organization.** Across all users, unassigned documents can add up to
  <Fact of={DOCUMENTS.maxUnassignedPerOrgMb} unit="MB" />. When the cap is reached, the upload shows
  "Your organization has run out of document storage. Ask your administrator to raise the limit.";
  finish or discard pending wizards to free up space.
- **They are removed automatically** after <Fact of={DOCUMENTS.unassignedRetentionHours} unit="hours" />.
  If you resume a wizard after that, the application asks you to upload the PDFs again; the title,
  signers and options are kept.

Each document belongs to one envelope only. If the wizard says a document is already part of another
envelope, remove it and upload it again.

## Place each signer's seal

When the envelope completes, bb-sign stamps on every document one seal per signer, with their name,
email, date, signature, hash and QR code (see
[Electronic signature and seal](/en/sign/concepts/signature-and-seal/)). You choose where each one
goes.

### With a marker

Write in the PDF, where you want the seal, the text <Fact of={DOCUMENTS.placementMarker} />,
replacing `N` with the signer's place in the list on the **Signers** step, counting from the top:
`{{signer1}}` for the first card, `{{signer2}}` for the second, and so on. With signing at once the
cards show no number, but the order still counts. You can use any font, as long as the PDF contains the marker as text and not as
an image. When sealing, bb-sign removes the marker and places the seal with its top-left corner where
the marker began.

bb-sign looks for each marker on every page. Signers with a marker get their seal at their marker,
and the others at the default position.

<Aside type="tip" title="Leave room under the marker">
  The seal is drawn downwards from the marker's line and takes the width of a signature with its
  details. Put the marker on a line of its own, with several blank lines below it, and test your
  template with a single-signer envelope before using it with customers.
</Aside>

### Without a marker

If the document has no marker for a signer, their seal goes to the **bottom-right corner of the
last page**. With several signers without markers, the seals stack upwards in that corner, in signer
order. If they do not fit on the last page, bb-sign adds a page at the end and continues there.

## Original and signed document

In the envelope detail, every document offers two downloads: **Original PDF**, the file as uploaded,
and **Signed PDF**, the same file with the seals stamped and the organization's certificate
signature. Next to each document is its fingerprint, "SHA-256 of the original:". The signed document
is available once the envelope is `COMPLETED`; while it is being generated, the detail shows
"Signed PDF processing...".

When the envelope completes, the detail adds the **Evidence certificate** block, with the downloads
**Evidence certificate (PDF)** and **Audit trail (JSON)**. See
[Evidence certificate](/en/sign/concepts/evidence-certificate/).

Downloading documents and the evidence certificate requires the Auditor role or higher in the
workspace; a Viewer sees their names. See
[Download signed documents](/en/sign/sending/download-signed-documents/).

## Each document's fingerprint

While it receives each PDF, bb-sign computes its SHA-256 fingerprint, a digest that changes
completely if a single byte of the file changes, and stores it together with the exact stored
version. On signing, each signature is bound to the fingerprints of the envelope's documents. If the
documents changed while a signer was reviewing them, bb-sign refuses the signature and shows "The
documents changed while you were reviewing them. Please review them again before signing.".
{DOCUMENTS.sealRefusedOnHashMismatch.value && ' Before sealing, bb-sign checks the fingerprints again: if the stored file no longer matches its recorded fingerprint, or the documents are no longer the ones each signer signed, it does not seal the document.'}

That is why the signed document corresponds exactly to the PDF you attached when sending the
envelope, and anyone can check it: the original's fingerprint appears in the envelope detail, in the
audit trail and in the evidence certificate.

## File retention

bb-sign keeps each file for <Fact of={RETENTION_IMPLEMENTED.documentsExpirationDays} unit="days" />:
the original from upload and the signed document from the envelope's completion. It then deletes it
permanently. In the envelope detail, the **Retention** block shows the date ("No longer available
from...") for each envelope.

Today no file is moved to archive storage: for the whole period, documents download directly. If a
file were ever archived, the detail says so and lets you request its restore; see
[Retention and restore](/en/sign/sending/retention-and-restore/). Keep in your own systems whatever
you must retain for longer. The terms are in [Scope and retention](/en/sign/legal/retention/).
