bb-sign exposes a small HTTP API for the envelope workflow, signed webhooks for what happens
afterwards, and two SDKs that wrap both. This page is the map of the section: what exists, where
it lives and in what order to read it.

## Production URLs

| | Value |
|---|---|
| API base URL | <Fact of={URLS.api} /> |
| Token URL (OAuth2 client credentials) | <Fact of={URLS.tokenUrl} /> |
| OpenAPI contract | <a href={URLS.api.value + URLS.openapiPath.value}><Fact of={URLS.api} /><Fact of={URLS.openapiPath} /></a> |
| Rendered API reference | [/sign/api/](/sign/api/) |

Set the first two as environment variables in anything that calls bb-sign. Tokens live
<Fact of={AUTH.tokenLifetimeSeconds} unit="s" />; both SDKs fetch and refresh them for you.

## What the public contract covers

The contract version <code>{openapi.info.version}</code> has {pathCount} paths ({operationCount}
operations) in five areas:

| Area | What it does | Credential needed |
|---|---|---|
| Documents | Upload a PDF before an envelope exists | Yes |
| Envelopes | Create, list, read, attach documents, add signers, send, cancel, counts by status | Yes |
| Signing ceremony | Open a link, request and verify a one-time code, sign, download the signed copy, open and close beacons | No: the link token is the credential |
| Verify | Check a seal from the QR code on a signed document | No |
| Workspaces | List the workspaces the credential can reach | Yes |

Everything a credential can call is scoped to its organization by the token, and within the
organization by its **workspace roles**. [Machine authentication](/en/sign/developers/authentication/)
explains both.

## What is not in the API

Managing organizations, users, certificates, quotas, API credentials, webhooks and workspaces are
**UI operations**: an org admin does them in **Settings**, and they are not part of the public
contract. The pages under [Administer the organization](/en/sign/admin/) document them. In
particular, a webhook is registered in **Settings**, tab **Webhooks**, not through an endpoint.

<Aside type="note" title="Only what is shipped">
  There are no templates, no bulk send, no form fields, no rate limits and no SDKs other than
  JavaScript and Java. If a page here does not describe it, it does not exist today.
</Aside>
