With the bb-sign API, your systems create and send envelopes, receive a signed notification each
time an envelope changes status, and download the signed document without manual steps. The
JavaScript and Java SDKs cover envelopes, documents, verification and webhook signature checks.
The evidence certificate, the workspace list and agreement copies are not in the SDKs: call them
over HTTP with the same token (see [JavaScript SDK](/en/sign/sdks/javascript/) and
[Java SDK](/en/sign/sdks/java/)).

## Production URLs

| | Value |
|---|---|
| API base URL | <Fact of={URLS.api} /> |
| Token URL (OAuth2 client credentials) | <Fact of={URLS.tokenUrl} /> |
| OpenAPI contract | <a href={URLS.api.value + URLS.openapiPath.value}><Fact of={URLS.api} /><Fact of={URLS.openapiPath} /></a> |
| API reference | [/sign/api/](/sign/api/) |

Set the first two as environment variables in every service that calls bb-sign. A token is valid
for <Fact of={AUTH.tokenLifetimeSeconds} unit="s" />; both SDKs fetch and refresh it
automatically.

## Public contract scope

Contract version <code>{openapi.info.version}</code> has {pathCount} paths ({operationCount}
operations) organized in these areas:

| Area | Operations | Credential required |
|---|---|---|
| Documents | Upload a PDF before creating the envelope | Yes |
| Envelopes | Create, list, read, attach documents, add signers, send, cancel, count by status; read and download the [evidence certificate](/sign/api/operations/getevidencecertificate/); [request a restore](/sign/api/operations/restoreenvelopedocument/) of an archived file | Yes |
| Signing ceremony | Open a link, request and verify a one-time code, sign, download the signed copy and the signer's certificate, request the archived copy, record open and close | No: the link token is the credential |
| Verify | Check a seal from the QR code on a signed document, or [upload the file](/sign/api/operations/verifydocumentfile/) to check its SHA-256 (limited to <Fact of={RATE_LIMITS.verifyFilePerMinutePerClient} /> requests a minute per client) | No |
| Workspaces | List the workspaces the credential can access | Yes |
| Agreement copies | [Read an immutable copy](/sign/api/operations/getagreementcopy/) of an agreement text, with its version, language and SHA-256 | Yes |

The token scopes every call to the credential's organization and, within it, to its **workspace
roles**. [Machine authentication](/en/sign/developers/authentication/) explains both levels, and
also what a credential reads outside the published contract: one envelope's audit trail, with the
`audit:read` permission.

{!AGREEMENTS.pinAtSendInProduction.value && (
  <p>In production, no envelope cites an agreement copy yet: copies are not pinned to envelopes when they are sent.</p>

## Administration operations

Organizations, users, certificates, quotas, API credentials, webhooks and workspaces are managed
in **Settings** by an organization admin. The pages under
[Administer the organization](/en/sign/admin/) describe each one. Webhooks, in particular, are
registered in **Settings**, tab **Webhooks**.
