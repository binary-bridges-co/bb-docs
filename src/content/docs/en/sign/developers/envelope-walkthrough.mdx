This guide walks through the complete integration flow: upload a PDF, create the envelope, add a
second signer, send it, receive webhook confirmation that everyone signed, download the sealed PDF
and check its hash, and keep the evidence certificate. It continues where the [quickstart](/en/sign/developers/quickstart/) ends. Each step shows the
same call in `curl`, JavaScript and Java; the tab you choose stays selected across the page.

Requirements: the four environment variables from the quickstart (`BBSIGN_BASE_URL`,
`BBSIGN_TOKEN_URL`, `BBSIGN_CLIENT_ID`, `BBSIGN_CLIENT_SECRET`), a PDF named `contract.pdf` and,
for the JavaScript and Java tabs, a `client` built as in the quickstart.

## 1. Get a token

Both SDKs fetch and refresh tokens automatically. The explicit token is needed for `curl` and for
the upload in step 2, which uses plain HTTP. A token is valid for
<Fact of={AUTH.tokenLifetimeSeconds} unit="s" />.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    TOKEN=$(curl -s -X POST "$BBSIGN_TOKEN_URL" \
      -d grant_type=client_credentials \
      -d client_id="$BBSIGN_CLIENT_ID" \
      -d client_secret="$BBSIGN_CLIENT_SECRET" | jq -r .access_token)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const tokenResponse = await fetch(process.env.BBSIGN_TOKEN_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: process.env.BBSIGN_CLIENT_ID,
        client_secret: process.env.BBSIGN_CLIENT_SECRET,
      }),
    })
    const { access_token: token } = await tokenResponse.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    HttpClient http = HttpClient.newHttpClient();
    String form = "grant_type=client_credentials"
            + "&client_id=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_ID"), StandardCharsets.UTF_8)
            + "&client_secret=" + URLEncoder.encode(System.getenv("BBSIGN_CLIENT_SECRET"), StandardCharsets.UTF_8);
    HttpRequest tokenRequest = HttpRequest.newBuilder(URI.create(System.getenv("BBSIGN_TOKEN_URL")))
            .header("Content-Type", "application/x-www-form-urlencoded")
            .POST(HttpRequest.BodyPublishers.ofString(form))
            .build();
    String tokenJson = http.send(tokenRequest, HttpResponse.BodyHandlers.ofString()).body();
    String token = new ObjectMapper().readTree(tokenJson).get("access_token").asText();
    ```
  </TabItem>
</Tabs>

## 2. Upload the document

`POST /api/v1/documents` takes multipart with one part, `file`. It accepts
<Fact of={DOCUMENTS.contentType} /> up to <Fact of={DOCUMENTS.maxUploadMb} unit="MB" />.
The response is an `UploadedDocumentResponse`; keep its `id`. A document that is not attached to an
envelope within <Fact of={DOCUMENTS.unassignedRetentionHours} unit="h" /> is deleted.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    DOCUMENT_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/documents" \
      -H "Authorization: Bearer $TOKEN" \
      -F "file=@contract.pdf;type=application/pdf" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { openAsBlob } from 'node:fs'

    const form = new FormData()
    form.set('file', await openAsBlob('contract.pdf', { type: 'application/pdf' }), 'contract.pdf')

    const upload = await fetch(`${process.env.BBSIGN_BASE_URL}/api/v1/documents`, {
      method: 'POST',
      headers: { Authorization: `Bearer ${token}` },
      body: form,
    })
    const { id: documentId } = await upload.json()
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    OkHttpClient okHttp = new OkHttpClient();
    RequestBody multipart = new MultipartBody.Builder().setType(MultipartBody.FORM)
            .addFormDataPart("file", "contract.pdf",
                    RequestBody.create(new File("contract.pdf"), MediaType.get("application/pdf")))
            .build();
    Request upload = new Request.Builder()
            .url(System.getenv("BBSIGN_BASE_URL") + "/api/v1/documents")
            .header("Authorization", "Bearer " + token)
            .post(multipart)
            .build();
    UUID documentId;
    try (Response response = okHttp.newCall(upload).execute()) {
        documentId = UUID.fromString(new ObjectMapper().readTree(response.body().string()).get("id").asText());
    }
    ```
  </TabItem>
</Tabs>

The generated SDK methods send JSON, so the multipart uploads in the JavaScript and Java tabs use
the platform HTTP client (okhttp is already a dependency of the Java SDK). You can also attach a
file to an existing draft with `POST /api/v1/envelopes/{id}/documents`, with the same part name.

## 3. Create the envelope

Send the document id in `documentIds`. `title` is the only required field; sending the envelope
requires at least one signer and one document.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    ENVELOPE_ID=$(curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes" \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d "{
        \"title\": \"Service agreement\",
        \"documentIds\": [\"$DOCUMENT_ID\"],
        \"otpRequired\": true,
        \"signers\": [{\"email\": \"ana@example.com\", \"name\": \"Ana Perez\", \"signOrder\": 1}]
      }" | jq -r .id)
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const envelope = await client.envelopes.createEnvelope({
      createEnvelopeRequest: {
        title: 'Service agreement',
        documentIds: [documentId],
        otpRequired: true,
        signers: [{ email: 'ana@example.com', name: 'Ana Perez', signOrder: 1 }],
      },
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    EnvelopeResponse envelope = client.execute(client.envelopes().createEnvelope(
            new CreateEnvelopeRequest()
                    .title("Service agreement")
                    .documentIds(List.of(documentId))
    ```

You can add signers while the envelope is in `DRAFT`. `signOrder` applies when

## 5. Send the envelope

On send, the documents and signers become fixed, each signer is emailed a link valid for
<Fact of={ENVELOPE.linkTtlHoursDefault} unit="h" /> by default, and `envelope.sent` is emitted. The
response is a `SendResponse` with each signer's signing tokens.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    curl -s -X POST "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/send" \
      -H "Authorization: Bearer $TOKEN"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const sent = await client.envelopes.sendEnvelope({ id: envelope.id })
    console.log('Sent', sent.envelopeId)
    ```

  <TabItem label="Java">

## 6. Receive `envelope.completed`

Register a webhook in **Settings**, tab **Webhooks**, subscribed to `envelope.completed` and
`envelope.evidence_issued`. When the last signer signs, bb-sign sends a signed event to your URL
**once** per envelope and subscription, with the evidence certificate when it is ready in time; if
it is not, the certificate follows in `envelope.evidence_issued`. Verify the signature over the raw
body, respond `2xx`, then process the event.

The payload carries the envelope, each document's SHA-256 (`data.documents[].signedSha256`), the
documents path, the evidence certificate's hashes and path, and the retention dates
(`data.retention`). The files are fetched in step 7. [Webhooks](/en/sign/developers/webhooks/)
describes delivery and retries.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```http
    POST /webhooks/bb-sign HTTP/1.1
    Content-Type: application/json
    X-BBSign-Event-Id: 3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f
    X-BBSign-Event-Type: envelope.completed
    X-BBSign-Signature: t=1760000000,v1=5f1a...

    {"id":"3f8c1e2a-7d44-4b1a-9c0e-5a6b7c8d9e0f","type":"envelope.completed","apiVersion":"2026-08-09",
     "createdAt":"2026-10-10T14:22:31Z","data":{"envelope":{"id":"...","title":"Service agreement",
     "status":"COMPLETED","createdAt":"...","expiresAt":null},
     "evidenceStatus":"ISSUED","signedDocumentsStatus":"READY",
     "documents":[{"documentId":"...","filename":"contract.pdf","originalSha256":"9f2c...","signedSha256":"4b7e..."}],
     "documentsPath":"/api/v1/envelopes/.../documents",
     "evidenceCertificate":{"evidenceId":"...","sha256":"c01d...","auditTrailSha256":"77aa...","language":"es",
      "downloadPath":"/api/v1/envelopes/.../evidence-certificate/download"},
     "auditChainHead":{"seq":12,"hash":"e3b0...","auditCoverage":{"level":"FULL","fullRows":12,"partialRows":0,
      "lastPartialAt":null,"reasons":[],"migratedAt":null}},
     "retention":{"archivesAt":null,"deletesAt":"2027-10-16T00:00:00Z"}}}
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import express from 'express'
    import { verifyWebhookSignature } from '@binarybridges/bb-sign-sdk/webhooks'

    const app = express()
    app.use(express.json({ verify: (req, _res, buf) => { req.rawBody = buf } }))

    app.post('/webhooks/bb-sign', (req, res) => {
      if (!verifyWebhookSignature(req.get('X-BBSign-Signature'), req.rawBody, process.env.BBSIGN_WEBHOOK_SECRET)) {
        return res.sendStatus(401)
      }
      const event = JSON.parse(req.rawBody.toString('utf8'))
      res.sendStatus(200)
      if (event.type === 'envelope.completed') void downloadSigned(event.data)
    })
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    @PostMapping("/webhooks/bb-sign")
    public ResponseEntity<Void> receive(
            @RequestHeader("X-BBSign-Signature") String signature,
            @RequestBody byte[] rawBody) throws IOException {

        if (!Webhooks.verify(signature, rawBody, System.getenv("BBSIGN_WEBHOOK_SECRET"))) {
            return ResponseEntity.status(401).build();
        }
        WebhookEvent event = MAPPER.readValue(rawBody, WebhookEvent.class);
        if (event.getType() == WebhookEvent.TypeEnum.ENVELOPE_COMPLETED) {
            executor.submit(() -> {
                downloadSigned(event.getData());
                return null;
            });
        }
        return ResponseEntity.ok().build();
    }
    ```

    `getType()` returns an enum (`WebhookEvent.TypeEnum`), not a `String`: compare it with its
    constants. `MAPPER` is the `ObjectMapper` from the [Java SDK](/en/sign/sdks/java/#verify-a-webhook)
    page, with ISO-8601 dates and no failure on new fields; an unconfigured `new ObjectMapper()`
    cannot read the event.
  </TabItem>
</Tabs>

## 7. Download the signed PDF and check its hash

`GET /api/v1/envelopes/{id}/documents` (the path in `data.documentsPath`) returns each document with
a `downloadUrl` (the original) and a `signedUrl` (the sealed copy). Both are presigned links valid
for <Fact of={ENVELOPE.downloadUrlSeconds} unit="s" />. Treat them as secrets: they grant access to
the file without a token. `signedUrl` is `null` when:

- the credential lacks `document:download` in the envelope's workspace;
- the signed copy cannot be downloaded now: `signed.availability` is `ARCHIVED`,
  `RESTORE_IN_PROGRESS` or `DELETED` (see [Retention and restores](/en/sign/developers/webhooks/#retention-and-restores)).
  {!RETENTION_IMPLEMENTED.documentsArchiveTransitionLive.value && 'Today no file moves to archive storage, so in production this happens only when the retention period ends.'}

Compute the SHA-256 of each downloaded PDF and compare it with `data.documents[].signedSha256`. If
`data.signedDocumentsStatus` is `PREPARING`, that hash is not known yet: do not compare it, and
download again later.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    DOCUMENTS=$(curl -s "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/documents" \
      -H "Authorization: Bearer $TOKEN")

    echo "$DOCUMENTS" | jq -r '.[0].signed.availability'   # AVAILABLE or RESTORED: downloadable
    curl -s -o contract-signed.pdf "$(echo "$DOCUMENTS" | jq -r '.[0].signedUrl')"
    shasum -a 256 contract-signed.pdf                      # must equal data.documents[0].signedSha256
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    import { createHash } from 'node:crypto'
    import { writeFile } from 'node:fs/promises'

    async function downloadSigned(data) {
      const expected = new Map((data.documents ?? []).map((d) => [d.documentId, d.signedSha256]))
      const documents = await client.envelopes.listEnvelopeDocuments({ id: data.envelope.id })
      for (const document of documents) {
        if (!document.signedUrl) continue // not downloadable now: see document.signed.availability
        const pdf = Buffer.from(await (await fetch(document.signedUrl)).arrayBuffer())
        const sha256 = createHash('sha256').update(pdf).digest('hex')
        const want = expected.get(document.id)
        if (want && want !== sha256) throw new Error(`SHA-256 mismatch for document ${document.id}`)
        await writeFile(`${document.id}-signed.pdf`, pdf)
      }
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    void downloadSigned(WebhookEventData data) throws Exception {
        Map<UUID, String> expected = new HashMap<>();
        if (data.getDocuments() != null) {
            for (WebhookEventDocument d : data.getDocuments()) {
                expected.put(d.getDocumentId(), d.getSignedSha256());
            }
        }
        List<DocumentWithUrlsResponse> documents =
                client.execute(client.envelopes().listEnvelopeDocuments(data.getEnvelope().getId()));
        HttpClient http = HttpClient.newHttpClient();
        for (DocumentWithUrlsResponse document : documents) {
            if (document.getSignedUrl() == null) {
                continue; // not downloadable now: see document.getSigned().getAvailability()
            }
            HttpRequest download = HttpRequest.newBuilder(URI.create(document.getSignedUrl())).build();
            byte[] pdf = http.send(download, HttpResponse.BodyHandlers.ofByteArray()).body();
            String sha256 = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(pdf));
            String want = expected.get(document.getId());
            if (want != null && !want.equals(sha256)) {
                throw new IOException("SHA-256 mismatch for document " + document.getId());
            }
            Files.write(Path.of(document.getId() + "-signed.pdf"), pdf);
        }
    }
    ```
  </TabItem>
</Tabs>

## 8. Keep the evidence certificate

When `data.evidenceStatus` is `ISSUED`, the [evidence certificate](/en/sign/concepts/evidence-certificate/)
is ready. `GET data.evidenceCertificate.downloadPath` answers JSON with `downloadUrl` (the PDF) and
`auditTrailUrl` (the frozen audit trail), both valid for
<Fact of={EVIDENCE.downloadLinkSeconds} unit="s" />, and their hashes. It requires
<code>{EVIDENCE.downloadPermission.value}</code>, and every call is recorded in the envelope's
audit trail. The SDKs do not include this route: call it over HTTP with the token from step 1. If
the status is `PENDING`, wait for `envelope.evidence_issued`.

<Tabs syncKey="lang">
  <TabItem label="curl">
    ```bash
    EVIDENCE=$(curl -s "$BBSIGN_BASE_URL/api/v1/envelopes/$ENVELOPE_ID/evidence-certificate/download" \
      -H "Authorization: Bearer $TOKEN")

    curl -s -o evidence-certificate.pdf "$(echo "$EVIDENCE" | jq -r .downloadUrl)"
    shasum -a 256 evidence-certificate.pdf                 # must equal .sha256 and data.evidenceCertificate.sha256
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    async function downloadEvidence(data) {
      const response = await fetch(`${process.env.BBSIGN_BASE_URL}${data.evidenceCertificate.downloadPath}`, {
        headers: { Authorization: `Bearer ${token}` },
      })
      const { downloadUrl, sha256 } = await response.json()
      const pdf = Buffer.from(await (await fetch(downloadUrl)).arrayBuffer())
      if (createHash('sha256').update(pdf).digest('hex') !== sha256) throw new Error('SHA-256 mismatch')
      await writeFile(`${data.envelope.id}-evidence-certificate.pdf`, pdf)
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    void downloadEvidence(WebhookEventData data) throws Exception {
        HttpClient http = HttpClient.newHttpClient();
        HttpRequest links = HttpRequest.newBuilder(
                        URI.create(System.getenv("BBSIGN_BASE_URL") + data.getEvidenceCertificate().getDownloadPath()))
                .header("Authorization", "Bearer " + token)
                .build();
        EvidenceCertificateDownloadResponse evidence = MAPPER.readValue(
                http.send(links, HttpResponse.BodyHandlers.ofString()).body(),
                EvidenceCertificateDownloadResponse.class);
        byte[] pdf = http.send(HttpRequest.newBuilder(URI.create(evidence.getDownloadUrl())).build(),
                HttpResponse.BodyHandlers.ofByteArray()).body();
        String sha256 = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(pdf));
        if (!sha256.equals(evidence.getSha256())) {
            throw new IOException("SHA-256 mismatch for the evidence certificate");
        }
        Files.write(Path.of(data.getEnvelope().getId() + "-evidence-certificate.pdf"), pdf);
    }
    ```
  </TabItem>
</Tabs>

Archive what you download: bb-sign keeps each file of the envelope for
<Fact of={RETENTION_POLICY.retentionDays} unit="days" /> (the signed copy from the completion and
the certificate from its issue), and `data.retention.deletesAt` says from which date they are no
longer available. Keeping them after that is the organization's responsibility. See
[Scope and retention](/en/sign/legal/retention/).

## Retry a POST that got no response

<Aside type="caution" title="List before you retry a write">
  If `POST /api/v1/envelopes` or `/send` times out, the outcome is unknown: the envelope may exist
  or may already have been emailed to the signers. The SDKs do not retry these calls and the API
  does not use idempotency keys. **List before you retry**: search by title with
  `GET /api/v1/envelopes?title=...` (or use `getEnvelope` if you kept the id) and send again only
  if the envelope is not there. The SDKs report this case as status `0`
  (`BbSignError.statusCode` in JavaScript, `BbSignException.statusCode()` in Java).
</Aside>

`429` and `503` are also retried for `POST`, because they indicate the server did not process the
request.

## Envelope workspace

The envelope in this walkthrough went to **General** because no `workspaceId` was sent. A
credential accesses the workspaces an admin assigned to it; `GET /api/v1/workspaces` lists them,
and each `EnvelopeResponse` includes `workspaceId` and `workspaceName`. Envelopes in workspaces the
credential cannot read return `404` and do not appear in lists.
